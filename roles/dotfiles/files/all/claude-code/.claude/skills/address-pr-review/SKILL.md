# Address PR Review Comments

**Goal:** Systematically work through every PR review comment with the user, track progress in a file, and post GitHub replies when each issue is resolved.

**Your Role:** Fetch comments, build a tracking file, present issues one at a time, wait for user confirmation, reply to GitHub, mark done. No auto-fixing without user sign-off.

---

## Step 1 — Identify PR

Try to detect the PR from the current branch:

```bash
gh pr view --json number,url,headRefName,title 2>/dev/null
```

If that returns nothing, ask the user for a PR number. Store as `$PR_NUMBER`.

---

## Step 2 — Fetch Comments

Fetch all three comment types in parallel:

```bash
# Inline review comments (on specific lines)
gh api repos/{owner}/{repo}/pulls/$PR_NUMBER/comments \
  --paginate \
  --jq '[.[] | {
    id: .id,
    node_id: .node_id,
    type: "inline",
    author: .user.login,
    is_bot: (.user.type == "Bot"),
    body: .body,
    path: .path,
    line: (.line // .original_line),
    url: .html_url,
    reply_url: .url,
    created_at: .created_at,
    in_reply_to_id: .in_reply_to_id
  }]'

# General PR-level review comments
gh api repos/{owner}/{repo}/pulls/$PR_NUMBER/reviews \
  --paginate \
  --jq '[.[] | select(.body != "" and .body != null) | {
    id: .id,
    node_id: .node_id,
    type: "review",
    author: .user.login,
    is_bot: (.user.type == "Bot"),
    body: .body,
    state: .state,
    url: .html_url,
    created_at: .submitted_at
  }]'

# Issue-style PR comments (general conversation)
gh api repos/{owner}/{repo}/issues/$PR_NUMBER/comments \
  --paginate \
  --jq '[.[] | {
    id: .id,
    node_id: .node_id,
    type: "issue_comment",
    author: .user.login,
    is_bot: (.user.type == "Bot"),
    body: .body,
    url: .html_url,
    reply_url: .url,
    created_at: .created_at
  }]'
```

To get `{owner}` and `{repo}`:
```bash
gh repo view --json nameWithOwner --jq '.nameWithOwner'
```

**Time filter:** If the user specified a time range (e.g. "since yesterday", "last 2 days"), filter by `created_at`. Otherwise include all comments.

**Exclude:**
- Comments where `in_reply_to_id` is set (these are replies, not root issues)
- Comments authored by yourself (check against `gh api user --jq '.login'`)

---

## Step 3 — Detect Severity

For each comment, assign severity based on keywords in the body:

- **blocking** — contains: `blocking`, `must`, `required`, `LGTM pending`, `changes requested`, `[h]`, `[high]`, `h:`, or review `state == "CHANGES_REQUESTED"`
- **suggestion** — contains: `[m]`, `[medium]`, `m:`, `should`, `suggest`, `consider`, `recommend`  
- **nit** — contains: `[l]`, `[low]`, `l:`, `nit`, `minor`, `style`, `optional`, `nitpick`
- **question** — contains: `?` and none of the above keywords
- **info** — everything else (bot summaries, coverage reports, etc.)

Order for the session: **blocking → suggestion → nit → question → info**

Within each severity group: file-by-file for inline comments, then general comments.

---

## Step 4 — Build Tracking File

Create `.pr-review-$PR_NUMBER.md` in the project root (or current directory if no project root detected):

```markdown
# PR #$PR_NUMBER Review Tracker
<!-- Generated by address-pr-review skill -->
<!-- PR: $PR_URL -->
<!-- Fetched: $TIMESTAMP -->
<!-- Total: $TOTAL_COUNT comments -->

## Progress: 0 / $TOTAL_COUNT done

---

## Blocking ($BLOCKING_COUNT)

### [ ] Comment #$ID — @$AUTHOR — $SEVERITY
**File:** `$PATH:$LINE` *(omit if not inline)*  
**Link:** $URL  
**Reply endpoint:** $REPLY_URL  
**Body:**
> $BODY

---

## Suggestions ($SUGGESTION_COUNT)

...

## Nits ($NIT_COUNT)

...

## Questions ($QUESTION_COUNT)

...

## Info / Bot ($INFO_COUNT)

...
```

Each comment block uses `### [ ]` when pending, `### [x]` when done.

Tell the user the file location and total counts before starting the session.

---

## Step 5 — Review Session Loop

Work through comments in severity order. For each pending (`[ ]`) comment:

### Present the comment

Show:
```
─────────────────────────────────────────
[$SEVERITY] #$ID by @$AUTHOR
$PATH:$LINE  (omit if not inline)
$URL

$BODY
─────────────────────────────────────────
```

If it's a bot comment, note: `[bot]` next to the author.

### Ask the user

```
Is this addressed? (yes / no / skip / done)
  yes   — mark done, post reply to GitHub
  no    — skip for now, come back later
  skip  — skip permanently (won't revisit)
  done  — end the session, save progress
```

Wait for the user's response. Do not proceed until they answer.

### On "yes"

1. Ask: "Reply to GitHub? Suggested: `[brief description of what was done]` — or type your own reply, or 'none' to skip reply."
2. If reply provided (not 'none'), post it:
   - For **inline comments** — reply to the thread:
     ```bash
     gh api repos/{owner}/{repo}/pulls/$PR_NUMBER/comments \
       --method POST \
       --field body="$REPLY_TEXT\n\n*— Claude Code*" \
       --field in_reply_to=$COMMENT_ID
     ```
   - For **review-level comments** — post a PR issue comment:
     ```bash
     gh api repos/{owner}/{repo}/issues/$PR_NUMBER/comments \
       --method POST \
       --field body="Re: $URL\n\n$REPLY_TEXT\n\n*— Claude Code*"
     ```
   - For **issue comments** — reply in the same thread:
     ```bash
     gh api repos/{owner}/{repo}/issues/$PR_NUMBER/comments \
       --method POST \
       --field body="$REPLY_TEXT\n\n*— Claude Code*"
     ```
3. Mark `[ ]` → `[x]` in the tracking file.
4. Update the progress counter: `Progress: X / $TOTAL_COUNT done`.
5. Move to next comment.

### On "no"

Leave `[ ]`, move to next comment. Will revisit if user runs the skill again (existing tracking file is loaded instead of re-fetching).

### On "skip"

Mark `### [~]` (skipped permanently). Move to next comment.

### On "done"

Save tracking file state. Print summary:
```
Session ended.
Done: X / $TOTAL_COUNT
Remaining: Y (no), Z (skipped)

Tracking file: .pr-review-$PR_NUMBER.md
Resume by running /address-pr-review again.
```

---

## Step 6 — Resume Behavior

On activation, check if `.pr-review-$PR_NUMBER.md` already exists for the detected PR:

- If yes: load it, skip already-done/skipped items, resume from first pending `[ ]` item
- If no: run from Step 2

---

## Constraints

- **Never auto-fix code.** This skill only tracks and replies — it does not touch source files.
- **Never post a reply without user confirmation.**
- **Never mark done without user saying "yes".**
- If a `gh api` call fails, show the error, ask the user if they want to retry or continue without posting.
